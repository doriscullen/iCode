# 连接 MCP 服务器

模型上下文协议（Model Context Protocol，MCP）服务器可以为 iCode 智能体提供外部工具、提示词模板和使用说明。本指南介绍如何在终端用户界面（Terminal User Interface，TUI）中连接 HTTP 或 STDIO MCP 服务器、配置可调用的工具，以及控制是否加载提示词模板、是否将服务器使用说明加入模型上下文。

连接 MCP 服务器前，请确认服务器来源可信。服务器可能接收工具调用参数，并访问本机文件、网络服务或账号数据；其提供的提示词模板和使用说明也可能影响智能体的行为。

## 添加 MCP 服务器配置

在输入栏中输入 `/agents mcp`，打开当前智能体的“MCP”标签页。添加的服务器配置只对当前智能体生效，不会自动应用到其他智能体。

每个服务器对应一张卡片。已保存的服务器默认折叠，只显示名称；点击名称可展开或折叠。保存时如果发现问题，有问题的卡片会自动展开。要删除服务器，点击卡片上的“✕”并确认。

点击“+ 添加”可复用其他智能体的 MCP 配置。有可复用配置时，弹窗会显示服务器名称、来源智能体，以及可执行文件名或 URL 主机名。选择后，完整设置会复制到列表顶部的新卡片中并展开。副本相互独立：之后修改或删除任一智能体中的配置，都不会影响另一方。复制已禁用的配置时，副本也保持禁用。弹窗读取当前智能体配置窗口中的最新草稿，包含尚未保存的修改。

多个智能体中设置相同的同名配置会合并显示，并列出所有来源；同名但设置不同的配置则分别显示。可选配置排在前面，灰色不可选配置排在后面，两组内分别按名称排序。灰色项会说明无法添加的原因：当前智能体已有同名配置，或已有连接、工具名称前缀相同且允许工具范围重叠的配置。已禁用的配置也会参与检查。

弹窗不会连接服务器。如果加载智能体时报工具名冲突，请按错误提示调整相关服务器的工具名称前缀，或排除重叠工具。单个服务器测试成功不能排除它与其他服务器的工具名冲突。

要配置新的服务器，选择“+ 新建 MCP 配置…”。如果其他智能体没有有效的 MCP 配置，“+ 添加”会直接创建空白卡片。无效的来源配置不会提供为候选。取消弹窗不会修改配置。复制和新建的配置都通过配置页现有的“保存”流程生效。

在新建卡片中填写以下字段：

1. 填写“服务器名称”。名称用于在当前智能体的 MCP 配置中标识该服务器。同一个智能体的 MCP 配置中，服务器名称不能重复，且不区分大小写。
2. 可选填写“描述”，用于备注服务器的用途。该描述不会作为服务器使用说明提供给智能体。

HTTP 请求头值和 STDIO 环境变量值都可以使用 `{{ENV_VAR}}` 引用启动 iCode 前已经设置的环境变量。环境变量名只能包含字母、数字和下划线，且不能以数字开头。

两者也可以用 `{{!command}}` 使用命令输出的内容，例如 `Bearer {{!tokenprovider gettoken}}`。命令需要满足的条件参阅[通过命令获取 API 密钥](../configuration/models.md#通过命令获取-api-密钥)。HTTP 服务器在 iCode 运行期间会获得新值；STDIO 服务器会一直使用启动时的值，只有 iCode 再次启动它时才会获得新值。如果命令第一次就失败，服务器连接失败。

手工编辑 YAML 时，请求头和环境变量中的数字值会作为文本读取。`timeout` 请填写不带引号的正整数；无效值需要修正后才能保存。

接下来，根据服务器的连接方式完成 HTTP 或 STDIO 设置。

### 使用 HTTP 连接

1. 将“传输方式”设为 `HTTP`。
2. 填写服务器 URL。URL 必须以 `http://` 或 `https://` 开头。
3. 如果服务器需要认证，在“请求头”中添加名称和值。可以用 `{{ENV_VAR}}` 引用启动 iCode 前已经设置的环境变量，例如：

   ```text
   名称：Authorization
   值：Bearer {{MCP_API_TOKEN}}
   ```

4. 如果当前网络要求该服务器不经过系统代理，启用“绕过代理”。
5. 建议保持 TLS 证书验证开启。如果需要连接已确认可信的自签名服务器，可以启用“跳过 TLS 验证”。启用后，iCode 不会验证 HTTPS 服务器证书，无法确认连接的是预期服务器。

HTTP 重定向必须保持请求方法不变，并且目标与原地址同源（协议、主机名和端口相同）；也允许同一主机在默认端口上从 HTTP 升级到 HTTPS。对于 POST 请求，可以跟随 `307`、`308` 重定向，例如补齐 URL 末尾的斜杠。如果重定向改变主机名或端口、将 HTTPS 降级为 HTTP，或将 POST 改为 GET，连接会失败；此时请直接配置预期的最终服务器 URL。

### 使用 STDIO 连接

1. 将“传输方式”设为 `STDIO`。
2. 在“命令”中填写用于启动服务器的程序名称或路径以及所需参数。TUI 会将这行内容拆分并分别保存到智能体 YAML 的 `command` 和 `args` 字段；手工编辑 YAML 时，应将可执行文件写入 `command`，将参数逐项写入 `args`。在 Windows 上，如果 `command` 是 `python` 或 `python3`，iCode 会跳过只提示从 Microsoft Store 获取 Python 的占位程序，改用 `PATH` 中下一个同名程序。python.org 的传统安装程序不提供 `python3`，并且只有在安装时选择了加入 `PATH`，`python` 才会在 `PATH` 中；否则请填写其 `python.exe` 的完整路径。
3. 按需添加该进程需要的环境变量。变量值可以直接填写，也可以用 `{{ENV_VAR}}` 引用启动 iCode 前已经设置的环境变量。直接填写的值会保留首尾空白；空值表示在服务器进程中将该变量设为空。

STDIO 连接会在本机启动指定程序。如果启动命令会下载或运行第三方软件包或脚本，应先确认其来源可信并检查相关内容。

## 从其他应用导入服务器

如果已经在其他应用中配置过 MCP 服务器，可以直接导入到当前 iCode 智能体，无需重新填写。目前支持 Claude Code、Codex、opencode 和 pi。

导入会保留服务器的连接配置、启用状态，以及能够转换的超时和工具范围设置。源应用为各个智能体单独设置的工具访问规则和工具审批规则不会迁移。导入后，调用工具是否需要你确认，由 iCode 的审批模式和规则决定，详见[配置审批模式](../configuration/approval.md)。

保存前请检查导入后的配置，并点击“测试”。变量缺失、连接失败等问题在测试或使用服务器时诊断，导入时不检查变量当前是否已设置。

1. 在“MCP”标签页中，点击“+ 添加”旁边的“从其他应用导入”。
2. 在左侧选择应用，在右侧查看其 MCP 服务器配置。点击服务器勾选框前的 ▶/▼ 可折叠或展开配置。
3. 勾选需要的服务器（点击勾选框或服务器名称），然后点击右下角的“导入”。导入前可以在多个智能体中勾选服务器。

已禁用的服务器在导入后仍保持禁用。查看“…中的作用范围”，确认服务器原本用于所有项目还是仅用于某个文件夹。导入后，使用当前 iCode 智能体的所有项目都可以使用这些服务器。iCode 在当前工作文件夹中启动 STDIO 服务器；如果服务器依赖某个特定文件夹，请在使用前调整命令或参数。

导入时会根据服务器名称生成“工具名称前缀”，避免工具重名。例如，名为 `github` 的服务器会把工具 `search` 提供为 `github_search`。名称中不支持的字符和超出长度限制的部分会自动调整。请检查生成的前缀，按需在服务器卡片中修改或清空（参见[命名与限制](#命名与限制)）。

导入后，请检查新增的服务器卡片。“描述”中会保留来源应用和导入时的提示，请在使用前处理这些提示。点击“测试”检查连接，再点击“保存”保留配置。

无论来自哪个智能体，导入时都需要注意：

- 配置值会原样复制，包括环境变量和请求头中的令牌、密码。iCode 将它们保存在智能体文件中，该文件只有你的用户账户可以读取。请求头值两端的空白会被去掉。
- 环境变量引用会转换为 iCode 的写法 `{{NAME}}`。请在启动 iCode 前设置这些变量：变量未设置时，iCode 会连接失败。
- OAuth 设置和登录状态不会导入，iCode 不会代办 OAuth 登录或令牌刷新流程。如服务器接受你提供的有效令牌，或支持其他认证方式，可按其要求配置认证请求头，例如 `Authorization: Bearer <access-token>`。直接填写的令牌过期后需自行更换；如果外部命令能够获取或刷新令牌，也可配置 `Bearer {{!tokenprovider gettoken}}`，参阅[手动迁移命令取值和请求头辅助命令](#手动迁移命令取值和请求头辅助命令)。
- iCode 没有对应选项的设置不会导入，提示中会列出它们，例如服务器的工作文件夹（iCode 总是在当前工作文件夹中启动服务器）。
- 命令或 URL 中使用了环境变量的服务器无法导入。部分环境变量或请求头的值也无法转换，例如 `{${TOKEN}}`。展开无法选择的服务器卡片可查看原因，再据此调整源配置或手动添加服务器。
- 当前智能体中已有相同设置的服务器无法再次选择。环境变量、请求头、启用状态或工具范围不同的服务器，即使命令或 URL 相同，也可以分别导入。如果“保存”时提示名称重复，请重命名其中一个服务器。
- 同一个服务器可能出现不止一次，例如既是“用户”服务器又是“项目”服务器，或者出现在两个智能体中。勾选其中一个后，设置相同的其他卡片会被锁定，并注明已勾选的是哪一个，因此该服务器只会导入一次。取消勾选即可改选其他卡片。
- 如果某个配置文件无法读取，或者该智能体自己也会拒绝其中的 MCP 设置，列表顶部会提示该文件，其中的服务器不会列出。

如果没有找到配置，表示没有找到支持的应用的 MCP 配置，即使应用已经安装也可能出现此提示。文件不得超过 16 MiB，JSON 文件的顶层须为 JSON 对象。请检查权限、大小和格式，修复后重新打开导入。

### Claude Code

iCode 会列出 Claude Code 使用的服务器，并沿用 Claude Code 的标注：

- “用户”：为所有项目添加的服务器，保存在 `~/.claude.json`（或 `CLAUDE_CONFIG_DIR` 指定文件夹中的同名文件）中。如果 Claude Code 的设置文件夹（`~/.claude`，或 `CLAUDE_CONFIG_DIR` 指定的文件夹）中有旧版 Claude Code 留下的非空 `.config.json`，Claude Code 会改读这个文件，iCode 也一样。
- “本地”：只为某一个文件夹添加的服务器，保存在同一个文件中。如果工作文件夹位于 Git 仓库中，列出的是为仓库顶层文件夹添加的服务器，Claude Code 在仓库内的任何文件夹中都使用它们；否则列出的是为工作文件夹本身添加的服务器。
- “项目”：工作文件夹或其任一上级文件夹中 `.mcp.json` 文件里的服务器。“只为当前项目”安装服务器的工具会把它写在这里。

Claude Code 自己不会加载的条目不会列出，例如有 URL 但没有 `type`、命令不完整、某项设置的类型不对，或名称是 Claude Code 留给自己服务器的（如 `workspace`）。此外：

- `${GITHUB_TOKEN}` 会转换为 `{{GITHUB_TOKEN}}`。`${HOST:-localhost}` 中的 `localhost` 这类默认值不会导入。请在启动 iCode 前设置变量，或将引用替换为需要的值。
- 变量引用会保持动态。HTTP 请求头变量提供的首尾空白不会在展开后去除，可能导致连接报 `Illegal header value`。请在启动 iCode 前去除变量值两端的空白。
- 变量未设置时，Claude Code 会把引用原样传下去，例如文本 `${API_KEY}`，并在 `claude mcp list` 中给出警告。iCode 则会连接失败，因此请在启动 iCode 前设置该变量。
- 服务器可能依赖 Claude Code 在配置之外提供的能力。iCode 不会设置 `CLAUDE_PROJECT_DIR`，也不提供 MCP roots。如果服务器需要该变量，即使配置中没有引用，也请在启动 iCode 前设置它。对于依赖 roots 的服务器，请确认它是否可以改用工作文件夹，或显式指定文件夹。
- 远程服务器请求头中的部分凭据变量引用（如 `ANTHROPIC_API_KEY`）会替换为空字符串，与 Claude Code 一致。其他文字会保留：`Bearer ${ANTHROPIC_API_KEY}` 会变成 `Bearer`，而只包含被移除引用的请求头会被省略。请检查认证请求头；如需发送该凭据，请把它复制到另一个名字的变量中再引用。
- 环境变量和请求头中的字面花括号会按 iCode 写法转义。只有发生转义时才会给出说明：`{{literal}}` 在配置中显示为 `{{{{literal}}}}`，服务器收到的仍是 `{{literal}}`。这是字面文本，不是环境变量引用。
- 服务器的单次调用超时会保留：Claude Code 以毫秒为单位的 `timeout` 会向上取整，换算为 iCode 以秒为单位的“MCP 请求超时”。预览会显示最终值；换算改变时长时，同时显示源配置的毫秒数，例如 1501 毫秒会导入为 2 秒。未配置超时的条目不会显示显式超时值。小于 1 秒的值会被忽略，Claude Code 也是如此。没有 `timeout` 但有 `request_timeout_ms` 的 HTTP 服务器改用该值，最长 5 分钟，与 Claude Code 一致。
- HTTP 配置的 `toolPermissions` 限制不会迁移。使用导入的工具前，请检查“可用工具范围”和审批规则。
- 请求头辅助命令、OAuth 设置和登录状态不会导入。如服务器接受你提供的有效令牌，或支持其他认证方式，可配置所需认证请求头。iCode 不会代办 OAuth 登录或令牌刷新流程。基于命令的请求头请参阅[手动迁移命令取值和请求头辅助命令](#手动迁移命令取值和请求头辅助命令)。
- SSE 和 WebSocket 服务器无法导入：iCode 只支持 STDIO 和 HTTP 服务器。`streamable-http` 类型按 HTTP 读取。
- iCode 要求远程服务器支持可流式 HTTP（Streamable HTTP）。如果“测试”失败，请确认服务器是否提供可流式 HTTP 地址；仅支持 SSE 的服务器即使在 Claude Code 中标为 HTTP，也无法连接。

### Codex

- “用户”：`~/.codex/config.toml` 中 `[mcp_servers]` 下的服务器，或 `CODEX_HOME` 指定文件夹中的 `config.toml`。相对的 `CODEX_HOME` 路径以当前工作文件夹为基准。
- “项目”：从项目根目录到工作文件夹之间各层的 `.codex/config.toml`，较近的文件优先。项目根目录是最近的包含 `project_root_markers` 中任一标记的文件夹（默认标记为 `.git`）；没有标记时，只搜索工作文件夹本身。多个文件配置同一服务器时，请检查卡片中的合并结果和列出的来源文件。

Codex 的项目信任状态不限制导入。由你选择哪些配置复制到当前 iCode 智能体；导入过程不会启动服务器，也不会修改 Codex 的信任设置。

此外：

- `command` 表示 STDIO，`url` 表示 HTTP。两者同时存在时无效，即使它们来自不同文件的合并。无效的服务器条目不会列出；文件无法读取或 TOML 格式错误时会显示错误。
- `env` 和 `http_headers` 中的值保持为字面量。预览中的花括号转义会有说明，服务器收到的仍是原来的花括号。`env_http_headers` 和 `bearer_token_env_var` 保留环境变量引用，不复制当前凭据值。环境变量请求头覆盖静态请求头，Bearer 认证覆盖 Authorization 请求头。
- 连接前请检查可选变量提示。Codex 可以跳过不可用或空值的可选请求头，并保留静态请求头作为回退；iCode 要求被引用的值非空。请在启动 iCode 前设置变量，或在导入后移除不需要的设置。显式引用的 `PYTHONPATH` 和 `PYTHONHOME` 也需要非空值。用于请求头的变量或命令输出应去掉首尾空白，且不能含有换行或控制字符，否则连接或实际发送的值可能与 Codex 不同。
- iCode 的 STDIO 服务器会继承比 Codex 更多的环境变量。启动 iCode 前，请取消设置不想传给导入服务器的变量，或使用干净的环境。从导入设置中省略的变量，仍可能从启动 iCode 的进程中继承。
- 已禁用的服务器保持禁用。请检查预览中的最终“MCP 请求超时”：小数秒向上取整，过大的值会降为支持的最大值。导入基线 Codex 0.166.0 的默认值为 300 秒。源配置的零超时会省略，改用 iCode 的默认请求超时；如有需要，请在导入后设置明确的值。iCode 也用该超时限制连接建立，Codex 独立的启动超时不会导入。
- 请核对预览中的“可用工具范围”。`enabled_tools` 只保留未被 `disabled_tools` 禁用的工具，空列表表示**无工具**。源配置只有禁用列表时，也会导入为**无工具**并显示提示。导入后，打开服务器设置，在“可用工具范围”中选择需要的工具。
- OAuth 设置和登录状态、ChatGPT／企业认证设置、审批规则和每工具输出上限不会导入。若需要认证，请打开导入服务器的“请求头”，按服务器要求提供有效令牌或其他认证请求头。iCode 不会代办 OAuth 登录或令牌刷新流程；可通过[外部凭据命令](#手动迁移命令取值和请求头辅助命令)获取令牌。请核对智能体配置文件中的[审批规则](../../reference/agent-profile.md#approval)。如需输出上限，可在[智能体配置文件](../../reference/agent-profile.md#toolsmcp)中设置服务器级 `max_tool_result_tokens`，但无法分别保留各工具的不同上限。
- 自定义 `cwd` 不会导入。若服务器依赖该目录，请从原目录启动 iCode，或在测试前调整服务器使用的相对路径。`http_headers_helper` 会有单独提示，说明[如何手动迁移](#手动迁移命令取值和请求头辅助命令)；导入过程中不执行辅助命令。远程执行环境或取自远程环境的变量不能作为本地服务器导入。
- Codex 因名称或字面值无效而跳过的请求头也会省略，并提示涉及字段。若需要该请求头，请修正源配置后重新打开导入。名称仅大小写不同且存在冲突的请求头无法导入，请先在源配置中为每个请求头只保留一项。变量名不受支持时，提示会指出应修正的源字段和变量名。

仅导入本地用户和项目配置文件。通过系统、托管或云端设置、选中的配置档、会话覆盖或插件提供的服务器和凭据，需要手动配置。请检查环境变量未导入的相关提示。

### opencode

iCode 会在以下配置位置查找 opencode 服务器。导入前，请核对每个服务器的最终设置：

- “全局”：`~/.config/opencode`（或 `XDG_CONFIG_HOME` 下的 `opencode`）中的 `opencode.json`、`opencode.jsonc` 和 `config.json`，`OPENCODE_CONFIG` 指定的文件，`~/.opencode` 文件夹，`OPENCODE_CONFIG_DIR` 指定的文件夹，`OPENCODE_CONFIG_CONTENT` 中的设置，以及管理员为所有用户安装的设置。
- “项目”：工作文件夹及其各级上级文件夹中的 `opencode.json`、`opencode.jsonc`，以及这些文件夹的 `.opencode` 文件夹中的同名文件，一直到 Git 仓库的顶层文件夹（不在仓库中时，一直到磁盘根目录）。设置了 `OPENCODE_DISABLE_PROJECT_CONFIG` 时会跳过它们，与 opencode 一致。

如果有多个配置来源修改同一个服务器，请查看“配置来源”和提示中的其他来源，定位需要核对或修正的设置。也请核对继承的环境变量或请求头，它们会传递给卡片中的服务器。opencode 从网上获取的设置（例如所在组织的设置）不会读取。

对于远程服务器，测试连接前请核对预览中的最终 URL 和请求头。

此外：

- `{env:GITHUB_TOKEN}` 会转换为 `{{GITHUB_TOKEN}}`。请在测试或使用服务器前设置被引用的变量。服务器收到的字面量花括号保持不变，预览中的花括号转义会有说明。用于请求头的变量应在启动 iCode 前去掉首尾空白。
- 命令或 URL 中含有环境变量引用的服务器无法导入，请手动添加服务器并填写明确的命令或 URL。整个 URL 写成 `{env:MCP_URL}` 或 `{file:url.txt}` 的服务器仍会列出，说明原因和涉及设置。
- 服务器名或配置字段名中含有 `{env:...}` 或 `{file:...}` 引用时无法导入，包括环境变量名、请求头名，以及 `command`、`type` 等设置的名称。请在源配置中将涉及的名称改为固定文字，然后重新打开导入；也可手动添加服务器并使用固定名称。
- 命令、URL、环境变量或请求头中用 `{file:...}` 读取文件的服务器无法导入。请手动添加服务器，并在自己的 iCode 配置中提供所需的值；支持时可使用环境变量或凭据命令，命令和 URL 则需要明确的值。变量名不受支持或花括号相邻的提示会指出需要修正或手动配置的设置。
- opencode 中已关闭（`"enabled": false`）的服务器，导入后也处于关闭状态。要使用它，请在其卡片中勾选“启用”。
- 请核对预览中的“MCP 请求超时”。值发生变化时会同时显示原毫秒数和最终秒数：小数秒向上取整，过大的值会降为支持的最大值。服务器未设置 `timeout` 时，使用 `experimental.mcp_timeout`；两者都未配置时，默认请求超时为 60 秒。iCode 也使用该值限制连接建立，而 opencode 的默认连接超时为 30 秒。
- 服务器的自定义 `cwd` 不会导入。请从提示中写明的基准目录解析相对 `cwd`，然后在测试前从得到的文件夹启动 iCode，或调整服务器使用的相对路径。
- 全局 `tools`、`permission`、`permissions`、`OPENCODE_PERMISSION` 和各智能体的权限规则不会迁移。请在 iCode 中配置“可用工具范围”和审批规则。
- opencode 默认启用 OAuth，只有 `oauth` 为 `false` 时才关闭。即使源配置没有显式填写 `oauth`，卡片也会提示 OAuth 登录无法导入。如服务器接受你提供的有效令牌，或支持其他认证方式，可配置所需认证请求头。iCode 不会代办 OAuth 登录或令牌刷新流程。
- 远程服务器不支持 HTTP 时，opencode 会改用 SSE 连接；iCode 不会。

如果配置错误导致服务器无法列出，请检查错误中指出的文件和设置。对于 MCP 服务器，请核对 `local` 或 `remote` 类型，以及相应的命令或 URL。修正配置后，重新打开导入。

### pi

iCode 会列出 pi 在工作文件夹中使用的服务器：

- “全局”：`~/.pi/agent`（或 `PI_CODING_AGENT_DIR` 指定的文件夹）中的 `mcp.json`。
- “项目”：工作文件夹本身的 `.pi/mcp.json`。项目服务器会替换同名的全局服务器。只用来开关某个全局服务器，或修改其工具提供方式的项目条目，会修改该全局服务器，并提示该项目文件。

pi 的项目信任状态不限制导入。由你选择哪些配置复制到当前 iCode 智能体；导入过程不会启动服务器，也不会修改 pi 的信任设置。

如果 pi 配置文件无法读取，请检查错误指出的文件、设置或行列位置。请保存为 UTF-8，使用没有注释或末尾多余逗号的有效 JSON，然后重新打开导入。此外：

- `${GITHUB_TOKEN}` 和 `$GITHUB_TOKEN` 会转换为 `{{GITHUB_TOKEN}}`，`$$` 转换为 `$`。以 `!` 开头的值是 pi 运行命令得到的输出。由于执行和刷新方式不同，不会自动转换为 iCode 的 `{{!command}}`；请[手动添加这类服务器](#手动迁移命令取值和请求头辅助命令)。
- pi 按原样处理的文本会保留，例如 `${TOKEN:-default}`，以及环境变量或请求头中的字面量花括号。预览中的花括号转义会有说明，服务器收到的仍是原来的文本。pi 不支持在变量引用中指定默认值。
- 含非 ASCII 字面文本的 HTTP 请求头无法在保持 pi 传输形式的前提下导入。请在 pi 配置中改用服务器接受的 ASCII 表示后重新打开导入，或继续使用 pi。请求头引用的变量也需要使用 ASCII 文本并去掉首尾空白，请在启动 iCode 前检查这些值。
- 命令或参数开头的 `~` 会转换为你的主文件夹。
- pi 中已关闭的服务器，导入后也处于关闭状态。请核对预览中的最终“MCP 请求超时”：未配置超时时保留 pi 默认的 60 秒，小数秒向上取整，过大的值会降为 iCode 允许的最大值。源配置不设超时上限时，会在最终值旁说明。服务器的 `description` 会放在导入后描述的开头。
- 自定义 `cwd` 不会导入。对于 `~` 路径，请使用提示中展开后的文件夹；相对路径应从提示中的基准目录解析。测试前，请从相应文件夹启动 iCode，或调整服务器使用的相对路径。
- pi 提供服务器工具的方式会转换为 iCode 的“加载策略”和“可用工具范围”：`codemode`（pi 的默认值）和 `deferred` 转换为“按需加载 — 需要时再加载工具”，`direct` 转换为“全部加载 — 一开始就加载全部可用工具”，`hidden` 转换为“无工具”。在 `toolExposure` 中逐个列出的工具，iCode 能表达时会加入工具列表；`"write_*"` 这类模式会在提示中列出。
- 无法导入的工具规则会改为遵循 iCode 中该服务器的整体设置，可用范围或加载方式可能与 pi 中不同。请核对预览中的最终“可用工具范围”“加载策略”，以及按需加载时的“初始可见工具”。导入后，可在该服务器设置中调整这些选项。
- OAuth 登录状态和 pi 的 `auth` 提供方凭据不会迁移。若服务器需要认证，请打开导入服务器的“请求头”，按服务器要求提供有效令牌或其他认证请求头。iCode 不会代办 OAuth 登录或令牌刷新；可通过[外部凭据命令](#手动迁移命令取值和请求头辅助命令)获取新令牌。直接填写的令牌过期后需要自行更换。未配置 `Authorization` 请求头或 `auth` 时，pi 默认使用 OAuth，这类服务器也会收到提示。pi 扩展添加的服务器不会列出。

### 手动迁移命令取值和请求头辅助命令

导入过程中不执行凭据命令或请求头辅助命令。源应用按字面量处理的文本会保持原样，包括环境变量或请求头中的 `{{!command}}`：导入并保存不会使它变成 iCode 的凭据命令。

对于 pi 中的 `!tokenprovider gettoken` 这类值，请手动添加服务器。在“环境变量”中，将相应变量设为 `{{!tokenprovider gettoken}}`。在“请求头”中，可以用 `Authorization=Bearer {{!tokenprovider gettoken}}` 获取令牌。如果命令输出的是完整的请求头值，请直接使用 `{{!command}}`，不要再添加一个 `Bearer` 前缀。

点击“测试”前，请核对以下差异：

- pi 在启动它的文件夹中运行取值命令，超时为 10 秒。iCode 在主文件夹中运行，超时为 30 秒。使用的 shell 和继承的环境变量也可能不同。如果命令依赖某个文件夹，请使用绝对路径，或用脚本自行设置工作文件夹。
- iCode 只接受一行非空、可打印的 ASCII 文本，去掉两端空白，最多捕获 64 KiB 输出。pi 接受去掉两端空白后的 UTF-8 输出，包括多行文本。供 iCode 使用的命令应只输出所需的值，并成功退出。详见[通过命令获取 API 密钥](../configuration/models.md#通过命令获取-api-密钥)。
- iCode 在设定间隔到期或收到 401 响应后刷新 HTTP 命令凭据。STDIO 服务器需要重新启动才能获取新值。HTTP 凭据刷新失败时，可能继续使用上一次的值。

Claude Code 的 `headersHelper` 和 Codex 的 `http_headers_helper` 返回包含多个请求头的 JSON 对象。请在 iCode 中逐项添加所需的请求头，引用环境变量，或使用只输出该请求头值的命令。不要将输出 JSON 的辅助命令填入 `Authorization={{!command}}`，否则会将 JSON 当作请求头值发送。如果多个请求头必须一起生成和刷新，请继续在源应用中使用该辅助命令。

## 配置说明、工具和请求选项

以下设置同时适用于 HTTP 和 STDIO 服务器。

### 服务器说明与提示词模板

- **将服务器使用说明加入模型上下文（如有）**：新建配置默认启用。启用后，服务器说明会加入模型上下文，并可能影响智能体的行为。
- **将服务器提示词模板加载为工具（如有）**：新建配置默认启用。启用后，服务器提供的提示词模板会作为可调用工具加入模型工具列表。

### 工具访问

- **可用工具范围**：控制允许智能体使用的服务器工具。可以选择“全部服务器工具”、“仅选定工具”或“无工具”。

选择“仅选定工具”时，填写以 `,` 分隔的工具名称列表。如果还不清楚服务器提供的工具名称，可以先选择“全部服务器工具”，再按照[测试并保存](#测试并保存)中的步骤从连接报告查看工具名称。

### 工具加载

- **加载策略**：控制工具何时提供给智能体。选择“全部加载 — 一开始就加载全部可用工具”时，“可用工具范围”内的所有工具在任务开始时即可使用。选择“按需加载 — 需要时再加载工具”时，任务开始时仅提供“初始可见工具（可选）”中的工具，智能体可在需要时加载“可用工具范围”内的其他工具。服务器提供的工具较多、常用工具较少时，按需加载可以减少任务开始时发送给模型的工具信息。
- **初始可见工具（可选）**：使用“按需加载 — 需要时再加载工具”时，可以填写以 `,` 分隔的工具名称列表。填写的工具必须包含在“可用工具范围”中。

例如：

- 服务器只提供 `search` 和 `read_file`，并且两者经常使用，可以选择“全部加载 — 一开始就加载全部可用工具”。
- 服务器提供几十个工具，但通常只使用 `search` 和 `read_file`，可以选择“按需加载 — 需要时再加载工具”，并将这两个工具填入“初始可见工具（可选）”。

使用 Claude Opus 5.5、Fable 5.1 或 Sonnet 5.5 时，按需加载有额外代价。这些模型会把返回的思考内容与它之前的对话绑定，包括智能体当时可用的工具。智能体加载或卸载工具，或下一个任务重新只从初始可见工具开始时，这部分对话就会变化，模型服务可能略去早先的思考内容，或拒绝读回这些内容。如果服务拒绝，iCode 会去掉早先的思考内容，再发送一次请求，这会多发一次请求。无论是服务略去，还是 iCode 去掉后重发，模型都不再看到那部分早先的推理。设为 `thinking_block_binding: error` 时，iCode 会直接报告这次拒绝，不会重发。相关设置详见 [Claude 思考设置](../configuration/models.md#claude-思考设置)。

### 命名与限制

- **工具名称前缀**：为该服务器的工具名称添加前缀，并使用 `_` 连接前缀与原名称。例如，前缀 `github` 会将工具 `search` 显示为 `github_search`。不同服务器或内置工具存在同名工具时，可以用前缀避免冲突。
- **MCP 请求超时（秒）**：限制单次 MCP 请求等待时间；留空时使用界面显示的默认值。

## 测试并保存

1. **启用/停用服务器**：如需启用 MCP 服务器，保持勾选配置卡片左下角的“启用”选项。如需保留配置但暂时停用服务器，取消勾选该选项。停用后，服务器不会向智能体提供工具、提示词模板或使用说明。
2. **测试服务器连接**：点击服务器配置卡片右下角的“测试”。iCode 会尝试连接服务器，并在连接报告中显示服务器身份、声明的能力和使用说明，以及当前配置下可用的工具和提示词模板。
3. **保存配置**：点击“保存”。如果修改的是当前会话正在使用的智能体，保存后的 MCP 配置会用于后续请求。

如果测试失败：

- HTTP 服务器应检查 URL、认证请求头、环境变量以及代理和 TLS 设置。
- STDIO 服务器应先查看连接错误中显示的可执行文件、工作目录、进程退出码和标准错误输出末尾，再核对命令、参数和环境变量，并确认命令能在所示工作目录中启动。iCode 只显示有限长度的标准错误输出；需要完整日志时，请按照服务器文档启用日志记录。分享诊断信息前，请移除令牌、凭据等敏感信息。

## 验证 MCP 工具调用

关闭智能体配置窗口，提交一项需要使用该服务器工具的低风险任务。例如，如果服务器提供只读搜索工具，可以要求智能体搜索一条明确的数据。

对话中应显示对应的 MCP 工具调用卡片，并返回服务器提供的数据。若弹出“工具审批”对话框，请先核对工具名称和调用参数，再决定是否批准。有关审批方式，请参阅[配置审批模式](../configuration/approval.md)。

如果工具返回的图像、音频或文件无法解码，智能体会收到一条简短说明代替该项，结果的其余内容照常送达。工具返回的链接会以文字（名称、地址和描述）交给智能体。

如果连接测试成功，但对话中工具不可用，请检查服务器是否已启用、工具是否出现在连接报告中，以及是否包含在“可用工具范围”中。

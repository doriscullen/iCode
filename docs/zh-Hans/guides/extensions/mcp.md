# 连接 MCP 服务器

模型上下文协议（Model Context Protocol，MCP）服务器可以为 iCode 智能体提供外部工具、提示词模板和使用说明。本指南介绍如何在终端用户界面（Terminal User Interface，TUI）中连接 HTTP 或 STDIO MCP 服务器、配置可调用的工具，以及控制是否加载提示词模板、是否将服务器使用说明加入模型上下文。

连接 MCP 服务器前，请确认服务器来源可信。服务器可能接收工具调用参数，并访问本机文件、网络服务或账号数据；其提供的提示词模板和使用说明也可能影响智能体的行为。

## 添加 MCP 服务器配置

在输入栏中输入 `/agents mcp`，打开当前智能体的“MCP”标签页。添加的服务器配置只对当前智能体生效，不会自动应用到其他智能体。

每个服务器对应一张卡片。已保存的服务器默认折叠，只显示名称；点击名称可展开或折叠。保存时如果发现问题，有问题的卡片会自动展开。要删除服务器，点击卡片上的“✕”并确认。

点击“+ 添加”，然后在列表顶部新增的卡片中填写以下字段：

1. 填写“服务器名称”。名称用于在当前智能体的 MCP 配置中标识该服务器。同一个智能体的 MCP 配置中，服务器名称不能重复，且不区分大小写。
2. 可选填写“描述”，用于备注服务器的用途。该描述不会作为服务器使用说明提供给智能体。

HTTP 请求头值和 STDIO 环境变量值都可以使用 `{{ENV_VAR}}` 引用启动 iCode 前已经设置的环境变量。环境变量名只能包含字母、数字和下划线，且不能以数字开头。

接下来，根据服务器的连接方式完成 HTTP 或 STDIO 设置。

### 使用 HTTP 连接

1. 将“传输方式”设为 `HTTP`。
2. 填写服务器 URL。URL 必须以 `http://` 或 `https://` 开头。
3. 如果服务器需要认证，在“请求头”中添加名称和值。可以用 `{{ENV_VAR}}` 引用启动 iCode 前已经设置的环境变量，例如：

   ```text
   名称：Authorization
   值：Bearer {{MCP_API_TOKEN}}
   ```

4. 如果当前网络要求该服务器不经过系统代理，启用“绕过代理”。
5. 建议保持 TLS 证书验证开启。如果需要连接已确认可信的自签名服务器，可以启用“跳过 TLS 验证”。启用后，iCode 不会验证 HTTPS 服务器证书，无法确认连接的是预期服务器。

HTTP 重定向必须保持请求方法不变，并且目标与原地址同源（协议、主机名和端口相同）；也允许同一主机在默认端口上从 HTTP 升级到 HTTPS。对于 POST 请求，可以跟随 `307`、`308` 重定向，例如补齐 URL 末尾的斜杠。如果重定向改变主机名或端口、将 HTTPS 降级为 HTTP，或将 POST 改为 GET，连接会失败；此时请直接配置预期的最终服务器 URL。

### 使用 STDIO 连接

1. 将“传输方式”设为 `STDIO`。
2. 在“命令”中填写用于启动服务器的程序名称或路径以及所需参数。TUI 会将这行内容拆分并分别保存到智能体 YAML 的 `command` 和 `args` 字段；手工编辑 YAML 时，应将可执行文件写入 `command`，将参数逐项写入 `args`。
3. 按需添加该进程需要的环境变量。变量值可以直接填写，也可以用 `{{ENV_VAR}}` 引用启动 iCode 前已经设置的环境变量。

STDIO 连接会在本机启动指定程序。如果启动命令会下载或运行第三方软件包或脚本，应先确认其来源可信并检查相关内容。

## 从其他智能体导入服务器

如果已经在其他智能体中配置过 MCP 服务器，可以直接导入到当前 iCode 智能体，无需重新填写。目前支持 Claude Code。

1. 在“MCP”标签页中，点击“+ 添加”旁边的“从其他智能体导入”。
2. 窗口左侧列出 iCode 在本机找到的受支持智能体。点击其中一个，右侧会显示它已配置的 MCP 服务器。每个服务器显示为一张卡片，列出导入后的配置：运行的命令或连接的 URL，以及环境变量或请求头及其值。
3. 勾选需要的服务器（点击勾选框或服务器名称），然后点击右下角的“导入”。导入前可以在多个智能体中勾选服务器。

对于 Claude Code，iCode 会列出 Claude Code 使用的服务器，并沿用 Claude Code 的标注：

- “用户”：为所有项目添加的服务器，保存在 `~/.claude.json`（或 `CLAUDE_CONFIG_DIR` 指定文件夹中的同名文件）中。
- “本地”：只为某一个文件夹添加的服务器，保存在同一个文件中。如果工作文件夹位于 Git 仓库中，列出的是为仓库顶层文件夹添加的服务器，Claude Code 在仓库内的任何文件夹中都使用它们；否则列出的是为工作文件夹本身添加的服务器。
- “项目”：工作文件夹或其任一上级文件夹中 `.mcp.json` 文件里的服务器。“只为当前项目”安装服务器的工具会把它写在这里。

“本地”和“项目”卡片会显示 Claude Code 在哪个文件夹中使用该服务器，列表顶部也会提示：导入后，iCode 会在所有项目中使用这些服务器。iCode 在当前工作文件夹中启动 STDIO 服务器，因此按启动位置确定项目的服务器，在每个项目中仍能正常工作。

Claude Code 自己不会加载的条目（例如有 URL 但没有 `type`，或命令不完整）不会列出。

导入的服务器会作为展开的新卡片出现在列表顶部。“描述”中注明了它来自哪个智能体，后面附上导入时的提示，关闭导入窗口后仍可查看；处理完后可以删掉这些提示。此时尚未保存：请检查卡片，可以点击“测试”，然后点击“保存”。

导入时需要注意：

- 配置值会原样复制，包括环境变量和请求头中的令牌、密码。iCode 将它们保存在智能体文件中，该文件只有你的用户账户可以读取。
- `${GITHUB_TOKEN}` 这类环境变量引用会转换为 iCode 的写法 `{{GITHUB_TOKEN}}`。iCode 不支持默认值：`${HOST:-localhost}` 中的默认值 `localhost` 会被丢弃，提示中会写明是哪个配置项和哪个变量。提示不会重复默认值本身，因此用作默认值的令牌不会被复制到“描述”中。请在启动 iCode 前设置该环境变量，否则连接会失败。
- Claude Code 会为它启动的 STDIO 服务器把 `CLAUDE_PROJECT_DIR` 设为项目文件夹，iCode 不会。每个引用了它的环境变量或请求头都会有提示：请在启动 iCode 前设置该变量，或改为写入文件夹路径。
- Claude Code 从不把它自身的几个凭据变量（如 `ANTHROPIC_API_KEY`）发给远程服务器，即使请求头中引用了它们。iCode 没有这条规则，会发送真实值，因此每个引用了这类变量的请求头都会有提示。请删除该请求头，或把凭据复制到另一个名字的变量中。
- 服务器的单次调用超时会保留：Claude Code 以毫秒为单位的 `timeout` 会向上取整，换算为 iCode 以秒为单位的“MCP 请求超时”。小于 1 秒的值会被忽略，Claude Code 也是如此。没有 `timeout` 但有 `request_timeout_ms` 的 HTTP 服务器改用该值，最长 5 分钟，与 Claude Code 一致。
- iCode 没有对应选项的设置不会导入，提示中会列出它们。对 Claude Code 来说是请求头辅助命令（iCode 不会运行它）和 OAuth 登录（iCode 只发送你填写的请求头），请手动添加请求头。其他 iCode 不认识的设置也会列出。
- 有些服务器无法导入：使用 STDIO 和 HTTP 以外连接方式（例如 SSE、WebSocket）的服务器，URL 或命令中使用了环境变量的服务器（iCode 会按原样读取这些字段），以及环境变量或请求头的值中花括号紧挨着环境变量引用的服务器（例如 `{${TOKEN}}`），iCode 无法写出相同的效果。它们的卡片显示为灰色虚线框，并说明原因。`streamable-http` 类型按 HTTP 读取。
- 当前智能体中已有的服务器（命令和参数相同，或 URL 相同）排在最后，显示为已勾选且不可更改，即使名称不同。如果导入的服务器与其他服务器同名，点击“保存”时会提示，请重命名其中一个。
- 同一个服务器可能出现不止一次，例如既是“用户”服务器又是“项目”服务器，或者出现在两个智能体中。勾选其中一个后，命令和参数相同或 URL 相同的其他卡片会被锁定，并注明已勾选的是哪一个，因此该服务器只会导入一次。取消勾选即可改选其他卡片。

## 配置说明、工具和请求选项

以下设置同时适用于 HTTP 和 STDIO 服务器。

### 服务器说明与提示词模板

- **将服务器使用说明加入模型上下文（如有）**：新建配置默认启用。启用后，服务器说明会加入模型上下文，并可能影响智能体的行为。
- **将服务器提示词模板加载为工具（如有）**：新建配置默认启用。启用后，服务器提供的提示词模板会作为可调用工具加入模型工具列表。

### 工具访问

- **可用工具范围**：控制允许智能体使用的服务器工具。可以选择“全部服务器工具”、“仅选定工具”或“无工具”。

选择“仅选定工具”时，填写以 `,` 分隔的工具名称列表。如果还不清楚服务器提供的工具名称，可以先选择“全部服务器工具”，再按照[测试并保存](#测试并保存)中的步骤从连接报告查看工具名称。

### 工具加载

- **加载策略**：控制工具何时提供给智能体。选择“全部加载 — 一开始就加载全部可用工具”时，“可用工具范围”内的所有工具在任务开始时即可使用。选择“按需加载 — 需要时再加载工具”时，任务开始时仅提供“初始可见工具（可选）”中的工具，智能体可在需要时加载“可用工具范围”内的其他工具。服务器提供的工具较多、常用工具较少时，按需加载可以减少任务开始时发送给模型的工具信息。
- **初始可见工具（可选）**：使用“按需加载 — 需要时再加载工具”时，可以填写以 `,` 分隔的工具名称列表。填写的工具必须包含在“可用工具范围”中。

例如：

- 服务器只提供 `search` 和 `read_file`，并且两者经常使用，可以选择“全部加载 — 一开始就加载全部可用工具”。
- 服务器提供几十个工具，但通常只使用 `search` 和 `read_file`，可以选择“按需加载 — 需要时再加载工具”，并将这两个工具填入“初始可见工具（可选）”。

使用 Claude Opus 5.5、Fable 5.1 或 Sonnet 5.5 时，按需加载有额外代价。这些模型会把返回的思考内容与它之前的对话绑定，包括智能体当时可用的工具。智能体加载或卸载工具，或下一个任务重新只从初始可见工具开始时，这部分对话就会变化，模型服务可能略去早先的思考内容，或拒绝读回这些内容。如果服务拒绝，iCode 会去掉早先的思考内容，再发送一次请求，这会多发一次请求。无论是服务略去，还是 iCode 去掉后重发，模型都不再看到那部分早先的推理。设为 `thinking_block_binding: error` 时，iCode 会直接报告这次拒绝，不会重发。相关设置详见 [Claude 思考设置](../configuration/models.md#claude-思考设置)。

### 命名与限制

- **工具名称前缀**：为该服务器的工具名称添加前缀，并使用 `_` 连接前缀与原名称。例如，前缀 `github` 会将工具 `search` 显示为 `github_search`。不同服务器或内置工具存在同名工具时，可以用前缀避免冲突。
- **MCP 请求超时（秒）**：限制单次 MCP 请求等待时间；留空时使用界面显示的默认值。

## 测试并保存

1. **启用/停用服务器**：如需启用 MCP 服务器，保持勾选配置卡片左下角的“启用”选项。如需保留配置但暂时停用服务器，取消勾选该选项。停用后，服务器不会向智能体提供工具、提示词模板或使用说明。
2. **测试服务器连接**：点击服务器配置卡片右下角的“测试”。iCode 会尝试连接服务器，并在连接报告中显示服务器身份、声明的能力和使用说明，以及当前配置下可用的工具和提示词模板。
3. **保存配置**：点击“保存”。如果修改的是当前会话正在使用的智能体，保存后的 MCP 配置会用于后续请求。

如果测试失败：

- HTTP 服务器应检查 URL、认证请求头、环境变量以及代理和 TLS 设置。
- STDIO 服务器应先查看连接错误中显示的可执行文件、工作目录、进程退出码和标准错误输出末尾，再核对命令、参数和环境变量，并确认命令能在所示工作目录中启动。iCode 只显示有限长度的标准错误输出；需要完整日志时，请按照服务器文档启用日志记录。分享诊断信息前，请移除令牌、凭据等敏感信息。

## 验证 MCP 工具调用

关闭智能体配置窗口，提交一项需要使用该服务器工具的低风险任务。例如，如果服务器提供只读搜索工具，可以要求智能体搜索一条明确的数据。

对话中应显示对应的 MCP 工具调用卡片，并返回服务器提供的数据。若弹出“工具审批”对话框，请先核对工具名称和调用参数，再决定是否批准。有关审批方式，请参阅[配置审批模式](../configuration/approval.md)。

如果工具返回的图像、音频或文件无法解码，智能体会收到一条简短说明代替该项，结果的其余内容照常送达。工具返回的链接会以文字（名称、地址和描述）交给智能体。

如果连接测试成功，但对话中工具不可用，请检查服务器是否已启用、工具是否出现在连接报告中，以及是否包含在“可用工具范围”中。
